# Global rules

## Working style
- Reply in Chinese, concise. Act directly; ask first only for irreversible or outward-facing actions.
- Verify before reporting done: run the project's build/tests and report failures with output.
- Before recommending, building, or scripting a tool or integration, survey what already exists (GitHub, plugin marketplaces, official plugin repos).

## Workstation
- Windows 11 + WSL2 Ubuntu; code projects live in WSL `~/projects/<category>/<name>`.
- TUI: WezTerm opens straight into herdr (workspace/agent manager; `cw [dir]` opens a project workspace with Claude) with plugins herdr-sidebar (file tree, auto-opens) and herdr-file-viewer (diff review); yazi popup, glow, lazygit, micro.
- When Git Bash calls `wsl.exe` with Linux paths, set `MSYS_NO_PATHCONV=1`.

## Shared config
- This file, `commands/`, `hooks/`, and the herdr/wezterm/yazi/micro configs live in this repo (claude-workstation). Edit them there.
- herdr keeps its socket in WSL `~/.config/herdr/`, so only `config.toml` is symlinked there (sockets can't live on /mnt/*).
- The `herdr` skill (`~/.claude/skills/herdr/SKILL.md`) is generated by the binary: after `herdr update`, regenerate it with `herdr --skill > ~/.claude/skills/herdr/SKILL.md`.
- A project opts into the Stop-hook check by adding an executable `.claude/verify.sh`.

## Lessons
- Windows repos use `core.autocrlf=true`. After copying one into WSL, rebuild the index (`mv .git/index .git/index.bak && git reset`) or git reports phantom changes.
